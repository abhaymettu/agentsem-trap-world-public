# HARSH-REVIEW.md

Hostile methods review of the agentSEM trap-world demonstration.

Sources reviewed in full (2026-09-16):
- `01-Projects/agentSEM/agentsem-synthesis-20260916.md` (196 lines)
- `01-Projects/agentSEM/agentsem-round1-deep-research.md` (297 lines)
- `01-Projects/agentSEM/agentsem-round2-method-expedition.md` (773 lines)

Scope: the trap-world demonstration only (good adaptive policy improves outcomes, leaves a
policy shadow, conventional SEM inflates person signal, policy-aware correction recovers truth).
No literature search was run; every claim below is derived from the specs' own algebra and
parameters. Every numeric prediction in B1, B2, and F1 to F5 was checked against a 4,000,000-draw
Monte Carlo on 2026-09-16 and matches the closed forms to three decimals.

---

## Verdict

The demonstration as specified will not produce its headline figure, and if it is built exactly
as written it will produce a result the authors will misread as a kill.

Three defects are load-bearing and all three are arithmetic, not opinion:

1. **The stated closed form predicts the opposite of the designated figure.** Under
   `eta = theta(1 + psi*kappa) + psi*kappa*e`, every correlation-based validation statistic
   against a clean criterion is *attenuated*, monotonically, as adaptivity rises. The factor
   `(1 + psi*kappa)` cancels out of any correlation. The figure "validation passes more as the
   agent gets better" cannot come from this equation. (B1)
2. **The prescribed specificity surrogate destroys the signal it is meant to protect.** At the
   spec's own T = 56 days, cumulative intervention dose is a 0.991-correlated proxy for theta.
   Partialling it removes 98.2% of true person variance. The benign arm does not survive this;
   the predicted innocent-kill rate is near 100%, not the hypothesized 5%. (B2)
3. **The trap world is not an instance of Theorem 1.** Theorem 1 requires logs to depend on
   `(theta, delta)` only through `eta`. In the trap world, `delta` is generated by the *logged*
   action sequence, so `delta` is measurable with respect to the log and the premise fails. The
   world is identified up to one scalar, which is why a correction can work at all. The synthesis
   sentence "the mechanism is Theorem 1's aliasing joined to the feedback loop" is wrong. (B3)

There is a real trap in here. It is not the one the specs describe. Two mechanisms do produce a
genuine, guaranteed "better agent, worse measurement" crossing, both derivable in closed form
before any code is written, both stronger than the current framing. They are given in B1.3 and
B1.4 as constructive replacements.

Build nothing until B1 through B5 are resolved in the spec text. Every hour spent on the
generator before then is spent building a world whose predicted output contradicts its own
design document.

## Blocking defects

Each must be fixed in the spec before the generator is written, because each changes what the
generator must contain.

### B1. The inflation claim is scale algebra misread as validity algebra

**Attacked claim** (synthesis, phase 10): "validation correlation is INFLATED by the factor
(1 + psi*kappa) as adaptivity kappa rises."

**The defect.** Write the spec's own linearization with `u = psi*kappa`:

```
theta ~ (0, s_th^2)
policy belief    th_hat = kappa*(theta + e),    e ~ (0, s_e^2), e independent of theta
measurement shift delta = psi*th_hat = u*(theta + e)
naive score      eta = theta + delta = (1+u)*theta + u*e
```

Then:

```
Var(eta)      = (1+u)^2 * s_th^2 + u^2 * s_e^2
Cov(eta,theta)= (1+u) * s_th^2
corr(eta,theta) = 1 / sqrt( 1 + [u^2 * s_e^2] / [(1+u)^2 * s_th^2] )
```

`u/(1+u)` is increasing in `u`, so **corr(eta, theta) is strictly decreasing in adaptivity.**
For any external criterion `C = lambda*theta + eps` with `eps` independent of `(theta, e)`:

```
corr(eta, C) = corr(eta, theta) * corr(theta, C)
```

so convergent validity against a clean criterion is attenuated by exactly the same factor. It
cannot rise. The `(1+u)` term is a scale factor and correlations are scale free; it survives only
in `Var(eta)`, in the regression slope of `eta` on `theta` (unobservable to the analyst), and in
covariances on an unstandardized scale.

**Why fatal.** The designated figure F1 is a crossing of naive-validation pass rate (up) against
true recovery (down). Under the spec's own equation, both curves go down. The sim will run, F1
will not appear, and the honest reading will be "the trap did not reproduce," when in fact the
prediction was never implied by the model.

**B1.1 Required fix.** Delete "validation correlation is inflated by (1 + psi*kappa)" from the
synthesis. Replace with a statement naming *which* statistic inflates and under which condition.
Pre-register the derivation as a unit test: the sim must reproduce `corr(eta, theta)` decreasing
in `u` and `Var(eta)/Var(theta)` increasing in `u`, both to within Monte Carlo error.

**B1.2 Consequence for the naive arm's scaling convention.** If the naive analyst standardizes
`eta` (the universal default in applied work), the `(1+u)^2` variance inflation is removed by
definition and only the `u^2 * s_e^2` noise term remains, which attenuates. A demonstration whose
"inflated person signal" disappears the moment the analyst types `scale()` is a strawman.
**Pre-register the naive arm's scaling convention explicitly and run both (standardized and
raw-scale) arms.** If the effect exists only in the raw-scale arm, say so in the abstract.

**B1.3 Constructive replacement 1 (guaranteed crossing, no criterion needed).** `delta` is a
*common* shift across all stream channels, because one policy moves all of them. Model p stream
indicators `y_j = theta + delta + eps_j`. Then the common-factor variance is
`V_c = (1+u)^2 * s_th^2 + u^2 * s_e^2`, monotone increasing in `u`, while residual variances are
fixed. Composite reliability rises monotonically:

```
rel = p*V_c / (p*V_c + s_eps^2)
```

Worked example, `s_th^2 = s_e^2 = s_eps^2 = 1`, p = 5:

| u = psi*kappa | reliability (omega) | corr(eta, theta) |
|---|---|---|
| 0.0 | 0.833 | 1.000 |
| 0.5 | 0.926 | 0.949 |
| 1.0 | 0.962 | 0.894 |

**Reliability up, validity down, guaranteed by the algebra, no contamination of the criterion
required.** This is the attenuation-paradox / method-factor story in a form a psychometrician
reads instantly, and it is a stronger F1 than the current one. It also makes "ordinary validation
passes" concrete: alpha rises, omega rises, unidimensional CFA fit improves, average variance
extracted rises. Every one of those is a checkbox in a standard validity paper.

**B1.4 Constructive replacement 2 (criterion-related validity, with a stated condition).**
Convergent validity against an external criterion can be inflated, but only when the criterion is
*downstream of the policy's actions*, which is exactly the case when the agent genuinely helps.
Let `O = gamma*dose + beta*theta + noise` with `dose` proportional to `th_hat`, and let
`r = gamma*dose-path share = g/(g+beta)` be the fraction of the theta-to-O association that runs
through the policy. Then

```
corr(eta, O) / corr(theta, O) = (1 + u + u*r) / sqrt(1 + 2u + 2u^2)
```

Two separate conditions fall out, and the specs contain neither.

**Condition 1, inflation at all.** `ratio > 1` for every `u > 0` requires
`r >= sqrt(2) - 1 = 0.4142`. Below that the curve dips under 1 at high adaptivity; at `r = 0`
(criterion untouched by the policy) it is attenuation everywhere, asymptote `1/sqrt(2) = 0.707`.

**Condition 2, the monotone rise the designated figure draws.** The ratio is hump shaped. It
peaks at

```
u* = psi*kappa = r / (1 - r)
```

and declines toward the asymptote `(1+r)/sqrt(2)` after. So to get a rise across a swept
adaptivity range `u` in `[0, U]`, you need `u* >= U`, that is

```
r >= U / (1 + U)
```

For a plausible `U = 2` that is `r >= 2/3`. Verified numerically (4M draws, sim matches the
closed form to three decimals):

| r | ratio at u=0.25 | u=0.5 | u=1 | u=2 | u=8 | peak at u* | rises over [0,2]? |
|---|---|---|---|---|---|---|---|
| 0.0 | 0.980 | 0.949 | 0.895 | 0.832 | 0.747 | none | no (attenuation) |
| 0.2 | 1.020 | 1.012 | 0.984 | 0.943 | 0.881 | u*=0.25 | no |
| 0.4142 | 1.062 | 1.080 | 1.079 | 1.062 | 1.023 | u*=0.71 | no |
| 0.6 | 1.098 | 1.139 | 1.162 | 1.165 | 1.146 | u*=1.5 | no |
| 1.0 | 1.177 | 1.265 | 1.342 | 1.388 | 1.412 | u*=inf | yes, ceiling 1.414 |

**The designated figure's monotone "validation passes more as the agent gets better" curve
requires `r` close to 1, meaning nearly the entire person-criterion association runs through the
policy's actions.** At the more realistic `r` of 0.2 to 0.4 the trap exists but turns over, and a
figure drawn across "none / greedy / learning" will show a hump, not a crossing. Both conditions
must be pre-registered, `r` must be a swept grid factor, and the sim's first job is reproducing
`u* = r/(1-r)` and the `sqrt(2)` ceiling, not reproducing `(1+psi*kappa)`.

Note what this reframes: the mechanism is not aliasing, it is that the naive score contains the
*cause* of the criterion. That is contaminated criterion validity, and it is a sharper and more
honest paper.

### B2. The specificity design rule is self-defeating at the spec's own parameters

**Attacked claim** (synthesis, phase 10): "partial what the policy DID (epoch, version,
cumulative dose, probe counts), never what the policy BELIEVED."

**The defect.** The rule assumes action-side surrogates are meaningfully distinct from the
belief. They are not, and the gap closes with the length of the study. Cumulative dose over T
occasions is proportional to `sum_t th_hat_t = T*kappa*(theta + e_bar)` with
`Var(e_bar) = s_e^2 / T`. So

```
corr(dose, theta) = 1 / sqrt(1 + s_e^2 / (T * s_th^2))
```

With `s_e^2 = s_th^2` and the spec's T = 56 days:

| surrogate window | corr(dose, theta) | theta variance left after partialling | signal attenuation factor |
|---|---|---|---|
| daily dose (T=1) | 0.707 | 50.0% | 0.707 |
| per-epoch dose (T=28) | 0.983 | 3.4% | 0.186 |
| cumulative dose (T=56) | 0.991 | **1.8%** | **0.133** |

Partialling cumulative dose removes about 98% of true between-person variance. A raw convergent
correlation of .35 becomes a partial correlation near .05. **The specificity test does not
separate the person from the policy; it deletes the person.**

**Why fatal.** This is not a risk, it is the expected value at the stated design. It predicts:
- the benign arm (`psi = 0`, `kappa > 0`) fails specificity at a near-100% rate, refuting the
  pre-registered hypothesis "the specificity test kills <= 5% of innocent benign arms";
- the guilty arm also loses its true signal, so "the correction recovers known truth" is
  unreachable by this route;
- both failures look like a *world* result and will be reported as one.

**B2.1 Required fix, conceptual.** Covariate adjustment on an action-derived quantity is
over-adjustment on a descendant of theta. It is not an identification strategy. The correction
must name which of D1 to D6 it instantiates and carry that design's identification argument.
Candidates that actually identify something in this world:
- **D1 (anchor):** a frozen common-policy window calibrates `f_0`; `delta` is the deviation from
  the anchored scale. Identification comes from the window, not from the regression.
- **D2 (randomization):** epsilon-greedy dose with logged propensities; IPW or DR; then positivity
  is checkable and the surrogate is the *exogenous* component of dose.
- **D4 (policy swap):** within-person contrast across a randomized epoch order.
- **D5 (parametric restriction):** `delta_i = psi * g(A_i)`; identified only if there is variation
  in `A` not driven by theta. Say where that variation comes from.

**B2.2 Required fix, mechanical.** The valid surrogate is the *residualized, exogenous* part of
the action: within-epoch deviations under randomization, or exogenous version dummies. State in
the spec that the surrogate set must satisfy a pre-run overlap check (see F6) and that failing it
returns `unsupported`, never a corrected point estimate.

**B2.3 The rule as written has a true core; state it narrowly.** "Never condition on the policy's
posterior mean" is correct. "Conditioning on the action is safe" is false whenever the action is a
smooth accumulating function of the posterior. The defensible form is: *condition only on action
variation that is exogenous to the person's state, and prove the exogeneity from the design.*

### B3. The trap world does not instantiate Theorem 1

**Attacked claim** (synthesis): "The mechanism is Theorem 1's aliasing joined to the feedback
loop."

**The defect.** Theorem 1's premise is that adaptive-phase logs `L = (Y, A)` depend on
`(theta, delta)` only through `eta = theta + delta`. In the trap world, `delta` accumulates with
intervention exposure and `A` is logged. Therefore `delta` is a measurable function of the log,
up to the scalar `psi` (and any person-specific `psi_i`). The premise fails. The observational
equivalence family `{(theta + c, delta - c)}` is not available, because `delta` is pinned by `A`.

This is not a pedantic point. It is why the demonstration's third leg is possible at all: **the
correction can recover truth precisely because the world violates Theorem 1's premise.** A demo
that satisfied Theorem 1 could not have a log-only correction, by the theorem.

**B3.1 Required fix.** Pick one and write it into the spec:
- **(a) Logged-action world (recommended).** State plainly that actions are logged, that Theorem 1
  therefore does not bite, and that the finding is: *even when the shadow's driver is fully logged
  and available, ordinary validation does not notice, and the fix is cheap.* That is a true,
  checkable, publishable claim and it is more useful to a practitioner than a nonidentification
  result.
- **(b) Unlogged-adaptation world.** If Theorem 1 is to be the mechanism, the shadow's driver must
  be unlogged (for example, a context-builder change or a silent model swap). Then the correction
  based on dose is impossible by construction and the only honest output is a bound or
  `unsupported`. This is the world that tests the certificate, not the correction.

**B3.2 The non-trivial theorem is one step away and is worth stating.** With person-specific
responsiveness `psi_i` (which round1 C5/C9 explicitly asserts: "personalization makes delta
person-specific"), `delta_i = psi_i * g(A_i)` with `psi_i` unobserved. If `psi_i` is correlated
with `theta_i` (highly plausible: the people who need more help both get more dose and respond
more to it), then no adjustment on `A` identifies `Var(theta)`, and the identified set is governed
by the unknown `Cov(psi, theta)`. **That is the version of the nonidentification result that is
both true in the trap world and non-trivial.** Derive it and use it; the current Theorem 1 is
"if you assume additive sufficiency then additive shifts are unidentified," which is definitional.

**B3.3 Internal contradiction to resolve.** The phase-10 closed form uses a single homogeneous
`psi`. Round1 C9 says `delta` is person-specific and the aliasing is heteroskedastic across
people. These cannot both stand. `psi_i` heterogeneity must be a swept factor in the grid, with
`Cov(psi, theta)` as its own axis.

### B4. Circular validation: the correction and the generator share a functional form

**Attacked claim** (build brief): "policy-aware agentSEM correction recovers known truth."

**The defect.** The generator makes `delta` accumulate with intervention exposure. The
pre-registered surrogate set contains cumulative dose. The correction partials cumulative dose. If
the correction then recovers truth, the finding is "a correctly specified estimator is
consistent." That is a unit test of the estimator, not evidence about the method, and it is the
weakest possible result to headline.

Worse: the surrogate list was written by someone who knew the generator's `delta` mechanism. That
is oracle leakage, and it is invisible in the results because there is no arm in which the
surrogate set is wrong.

**B4.1 Required fix: a misspecification grid on the *correct* model, not only a strawman
alternative.** The spec's "deliberately misspecified alternative" attacks a competitor. The
correction itself must be attacked. Minimum four `delta` generators, crossed against one fixed,
frozen surrogate set:

| `delta` generator | surrogate match | required certificate output |
|---|---|---|
| G1 cumulative dose, homogeneous psi | exact | `identified`, bias within tolerance |
| G2 recency-weighted dose (exponential decay, half-life swept) | partial | `bounded`, CI covers truth |
| G3 heterogeneous `psi_i`, `Cov(psi, theta)` swept over {0, .3, .6} | partial | `bounded` or `unsupported` |
| G4 driver is an **unlogged** context-builder change | none | `unsupported`, no point estimate |

**G4 is the single most important cell in the entire study.** If the audit returns a corrected
point estimate under G4, the false-confidence metric is measuring nothing and the certificate is
decorative. Pre-register G4 as a kill test for the framework.

**B4.2 Freeze the surrogate set before the generator library exists,** and record its hash in the
results file. Any surrogate added after seeing a generator is leakage and must be reported as an
exploratory arm.

### B5. Estimand drift across the three documents, and against the project's own theorem

Round1 (Sec 2.2) sets the primary reverse estimand to `E1 = sigma^2_theta` on the reference-policy
scale. Round2 (Sec 13, "Died or was cut") kills "an all-purpose latent user trait recovered from
ordinary logs" and recommends the recoverable subspace or interventional predictive state instead.
The synthesis's trap world then recovers a named person construct (task-deferral propensity) from
ordinary adaptive logs and reports it as the success condition.

**The trap-world success condition is the object round2 killed.** Additionally, round1's Theorem 1
says `Var(theta)` is not point-identified from adaptive logs alone, so "correction recovers known
truth" either (a) uses information beyond the logs, or (b) contradicts the project's own theorem.

**B5.1 Required fix.** Name the extra information the correction consumes, in one sentence, in the
spec. The honest answer appears to be the mid-study embargo boundary: an exogenous policy version
change is a D1-flavored anchor, and it is the source of identification. If so, the claim becomes
"the correction is identified because the deployment happens to contain an exogenous policy
change, and the certificate's job is to detect whether a deployment has one." That is coherent,
defensible, and directly motivates the certificate product.

**B5.2 Pre-register ONE primary estimand with a tolerance.** Candidates have different
identification status and cannot be pooled into "recovers truth":
- `Var(theta)` on the pi_0 scale (scale dependent, sensitive to B1.2);
- `beta` in `outcome ~ theta` (scale free, decision relevant, recommended primary);
- rank correlation of `theta_hat` with `theta` (insensitive to the whole trap; do not use as
  primary, it is the statistic Corollary 1.1 already says survives);
- a subgroup contrast in SD units.

Report bias, RMSE, **and** CI coverage for all of them. The build brief's "bias/coverage **or**
calibrated uncertainty" is a loophole: a two-stage correction has a generated-regressor problem,
so analytic standard errors after partialling estimated surrogates are wrong. Require a
person-level bootstrap over the full pipeline and report empirical coverage against nominal.

## Serious defects

Fix before the grid runs. Each of these changes a result, not just a sentence.

### S1. The embargo boundary is doing silent identification work and its exogeneity is assumed
If the mid-study version change is exogenous, it anchors the scale (see B5.1). If it is triggered
by observed performance (realistic: teams ship when a metric dips), the anchor is endogenous and
every epoch-dummy adjustment is invalid. **Make the embargo trigger a swept factor: exogenous
(calendar) versus performance-triggered. Report whether the certificate can tell the difference
from the log alone.** If it cannot, that is a named limit of the audit and belongs in the claim
card, not in a footnote.

### S2. Positivity is never checked in the trap world although round1 C6 flags it
A greedy Kalman-driven intensity is deterministic given history. In finite samples the surrogate
design matrix will not be exactly rank deficient (filter noise creates variation), so the
regression *will* run and return a silently ill-conditioned number. No error, wrong answer.
**Required: emit condition number and VIF for the surrogate design matrix, and `R^2(dose ~ th_hat)`,
in every run. Pre-register a threshold (recommend `R^2 > 0.9` or VIF > 10) above which the
certificate returns `unsupported`.** This is the concrete implementation of round2's own acceptance
test "zero propensity in a requested region produces `unsupported`."

### S3. The benign arm as described is not a specificity check
The synthesis gives two incompatible descriptions: the figure caption says "adaptation confined to
a calibrated, invariant bank," and the innocence unit test says `psi = 0`. These are different
worlds. The bank world may also remove the dose-theta coupling, which makes the adjustment variable
irrelevant and the check vacuous. **A real specificity check holds everything fixed except the
shadow: same policy, same kappa, same dose-theta coupling, `psi = 0`.** State that and delete the
"invariant bank" wording from the figure caption, or run both as separate arms and label them.

### S4. Specificity is reported as a pass/fail with no power curve, and uses non-rejection as evidence
"The correlation survives partialling" is a non-rejection. Round2 Sec 5.1 already requires
equivalence testing against a predeclared smallest meaningful difference; the synthesis's
specificity falsifier reverts to significance-style language. **Resolve in favour of round2:
specificity must be a TOST-style equivalence decision against a tolerance from the claim card.**
Report an ROC over graded `psi`, not a single pass rate. A test with a 5% innocent-kill rate and no
power against `psi > 0` is a coin that says "innocent."

### S5. No false-refusal metric
A certificate that returns `unsupported` everywhere has a zero false-confidence rate and zero
value. **Add a false-refusal rate (returns `unsupported` when the estimate would have been within
tolerance) and report the two rates as a pair, on one axis, per cell.** Without it the audit arm
is unfalsifiable in the direction that matters commercially.

### S6. Ordinary validation is not adversarially chosen, and the strongest ordinary test is missing
The naive+validation arm runs convergence with ESM, correlation with PHQ-9, and incremental
prediction. Standard practice in this literature also includes **longitudinal measurement
invariance testing (configural / metric / scalar), which round1 itself imports as C1's remedy and
which is designed precisely to detect a response-function shift over time.** A policy-induced shift
accumulating across an epoch boundary is close to the canonical case that test detects.

**If invariance testing catches the trap, the paper's central claim ("standard validation passes")
is false and the contribution collapses to "run the test you already should have run." This is
the most likely single kill for the whole study and it is absent from the spec's kill list.**
Add it to the kill list, implement it in the validation battery, and pre-register the narrower
surviving claim (for example: invariance testing catches it only above some `psi`, or only with
enough occasions per epoch, or is not in practice run on stream-derived indicators).

Also add: test-retest reliability, discriminant validity against a nuisance construct, and
multitrait-multimethod structure. A three-test battery that happens to be fooled is not "ordinary
validation."

### S7. Two ordinary preprocessing steps may destroy the trap
`delta` accumulates with exposure, so it is largely a within-person trending quantity, while
`theta` is stable by design. Person-mean centering removes stable `theta` and the between-person
part of `delta`; linear detrending removes `delta`'s trend. **Both are routine.** Add an arm
labelled "competent-analyst preprocessing" (person centering + linear detrend + epoch fixed
effects) and report whether the false signal survives it. If it does not, the paper's claim must
narrow to analysts who do neither, and that must be in the abstract.

### S8. The competitor set is too thin to support an incremental-contribution claim
Seven analyzers minimum, on the same axes: (i) naive; (ii) naive + person fixed effects;
(iii) epoch/time fixed effects only; (iv) adjust for `th_hat` (the forbidden belief conditioning,
included deliberately to demonstrate over-correction); (v) IPW/DR under the randomized arm;
(vi) partial-invariance longitudinal model (D3); (vii) the agentSEM correction.

**If (iii) epoch fixed effects alone repair the case, the framework contribution is dead** by the
specs' own kill condition ("adds terminology but no better decisions than existing diagnostics").
Pre-register that as an explicit kill test rather than discovering it in review.

### S9. "The better the agent works, the stronger the fake signal" is tautological as parameterized
`gamma` (true help) and `psi` (shadow) are both driven by dose, so the correlation between agent
quality and shadow strength is built in. **Sweep `gamma` and `psi` as an independent 2-D grid,
including `gamma > 0, psi = 0` (good agent, no shadow: validation and recovery should both be
fine) and `gamma = 0, psi > 0` (useless agent, full shadow).** The non-tautological claim is
"conditional on `psi > 0`, false confidence increases in `gamma`," and it requires the criterion to
be policy-downstream (B1.4).

Add one more arm that reframes the whole paper honestly: a policy that helps everyone *equally*
(dose uncorrelated with theta, `gamma > 0`). It should produce no shadow. If it does not, the
correct headline is **"personalized help, not help, creates the trap,"** which is more defensible
and more interesting than the current wording.

### S10. The criterion's causal position is never stated, and it determines everything
Three possible positions for ESM / PHQ-9, with different predictions:
1. pure measure of theta, untouched by policy: convergent validity **attenuates** (B1);
2. affected by the policy's actions (because the agent works): convergent validity **inflates**,
   subject to `r >= 0.4142` (B1.4);
3. collected *by the agent*, with policy-driven compliance: the trap is selection / missingness,
   not shift. The spec's "ESM-compliance joins the grid" amendment gestures at this without making
   it a mechanism.

**Implement all three, report which produces the crossing curves, and state in the abstract which
one the headline rests on.** If only (1) is implemented, F1 will not appear.

### S11. The Kalman policy is an unrealistically well-specified adversary
Kalman innovations are orthogonal to the estimate by construction, which is what makes the closed
form clean. Real policies use misspecified heuristics, under which `e` correlates with `theta`,
with subgroup membership, and with dose, and the `(1+psi*kappa)` form is wrong. **Add at least one
arm with a heuristic policy (threshold on a single noisy channel).** Separately, the figure's third
adaptivity level is "learning": a learning policy has a time-varying gain, so `delta` accumulation
is nonstationary and cumulative dose is a poor summary of it. Test that cell explicitly rather than
interpolating.

### S12. Probe counts are simultaneously the instrument and a nuisance covariate
The surrogate set includes probe counts. But probes under D2/D6 are the identifying randomization.
Residualizing on them adjusts away the identifying variation. **Resolve: randomized probes enter as
design (weights or strata), never as covariates to be partialled.** Remove probe counts from the
surrogate list or split it into "exogenous probes (design)" and "endogenous probe triggers
(covariate)."

### S13. Monte Carlo design is under-specified and the headline is an interaction
500 sims/cell is justified by SE ~2% on a marginal rate at 0.5. The headline is a *crossing* and an
*interaction* (false confidence rises in kappa AND in gamma), which needs more. Meanwhile
full-factorial over adaptivity x true effect x response shift x probe budget x drift x
ESM-compliance, plus the new axes required above (`r`, `Cov(psi,theta)`, delta-generator, criterion
position, embargo trigger, policy specification), is a combinatorial blowup.

**Required: pre-register the exact cell list, total sim count, and runtime budget before running.**
If it does not fit, use a screening design (fractional factorial or Latin hypercube) with a
metamodel and say so. Also pre-register the multiplicity family across the five hypotheses and its
correction, otherwise the "<= 5%" claims are uncontrolled. Report Monte Carlo SE on the
*difference* between arms, not just within-arm.

### S14. Pass rates at .2/.3/.4 thresholds can manufacture a crossing
With N = 200, the SE of a correlation is about .07. A binary pass rate at a fixed threshold is
dominated by where the sampling distribution sits relative to the threshold, so two curves can
cross for threshold reasons alone. Threshold sensitivity is already planned, which is good.
**Add: report the full distribution (mean and quantiles) of each raw validation statistic per cell,
and show the crossing is present in the continuous statistics, not only in the thresholded rates.**

### S15. Leakage channels in the estimation pipeline
- **Encoder feedback (round1 C11).** If the stream summary `phi` is learned from the same adaptive
  logs used for evaluation, it absorbs the policy fingerprint. State whether `phi` is fixed by
  design or learned. If learned, enforce frozen calibration splits and add a test that fails when
  the split is violated.
- **Seeds.** "Deterministic seeds" is insufficient. Use independent RNG streams per component
  (spawned child seeds), and add a test that reordering or parallelising cells does not change
  results. A single global seed shared between generator and bootstrap correlates errors across
  arms and will flatter the correction.

### S16. Dangling spec reference: the study-one parameterization does not exist
The synthesis says "Full parameterization in the working notes" for the N = 200 / 56-day design.
A grep across the entire vault on 2026-09-16 returns only the three files under review; no working
notes exist. **Every number the builder needs (drift AR coefficient, Kalman gain range, `psi`
range, `gamma` range, subgroup proportions, dose function, epoch timing, noise variances) is
currently unspecified.** Whoever writes the generator will invent them, and invented parameters are
exactly where a trap can be tuned into existence. Write the parameter table into the spec, with a
justification per parameter, before the generator exists.
